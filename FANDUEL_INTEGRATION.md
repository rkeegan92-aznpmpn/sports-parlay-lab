# Independent FanDuel REST integration

Implemented against https://fanduelapi.com/docs, its linked `/openapi.json`, `/fanduel-nfl-props.md` and `/fanduel-api-pagination.md` (reviewed November 11, 2026, America/Phoenix). This is the independent FF API Inc. service, **not an official FanDuel API**. No FanDuel login, account signup, paid plan, credit purchase or wager is performed.

## Configuration and use

Add the provider-issued `FANDUEL_API_KEY` privately to **`nfl-parlay-lab/.env.local`**, the existing Next.js application directory, or the server's environment. Restart the application after changing credentials. The root `.env.local` is not the nested application's Next.js environment file. Existing process bindings take precedence under Next's standard environment loading. Never use a `NEXT_PUBLIC_` variable or paste the key into chat, URLs or diagnostics. No existing environment file is rewritten by this change.

The default free-data page now includes **FanDuel API — aggressive pregame research** above the existing manual workflow:

1. **Fetch NFL events and props** requests authenticated REST data on the server, normalizes it, verifies events against the free schedule and matches players through the existing statistics/roster/injury pipeline.
2. Inspect **Actual provider prices and freshness**, including line, side, American price, observation time, feed `as_of`, reported delay and source status.
3. **Generate Two Aggressive Options from cache** reruns eligibility against current time without another provider request. Both options use the existing aggressive ranking and eligibility rules. They must contain different selections; overlap is penalized, not prohibited. Missing alternatives produce an explicit block, never invented picks.
4. Save either option to existing Saved Tickets. Both archive as aggressive Pending research tickets; provider identifiers, timestamps and delay metadata remain in the saved selection JSON. TEST MODE is preserved. The existing free grading worker uses the verified NFL result-game identity and ESPN bridge after final results exist.

Root development launch remains `npm run dev`; production remains `npm run build` then `npm start`. `npm run codespace:start` starts/reuses the development preview. Development now uses `.next-dev` and production `.next`, preventing an active preview from overwriting production chunks during builds. DB_PATH, saved-ticket schema, historical records and prior provider/manual/first-quarter features are retained.

## Contract and safeguards

- Server requests go only to `https://fanduelapi.com/api/v1/events` and `/props` with `Authorization: Bearer …`, `sport=nfl`, `limit=200` and increasing offsets. Props request `status=open`. Redirects are refused so credentials cannot be forwarded elsewhere; requests have a 20-second timeout.
- `meta.has_more` controls paging. Missing metadata, malformed JSON, empty/repeating nonterminal pages or more than five pages per endpoint fail clearly. A refresh can spend up to ten requests; an incomplete board never generates tickets. The safety budget is intentionally conservative for the documented 50-request/month free plan; unusually large boards may require a future scoped-event implementation after actual coverage is known.
- Page loads do not call the provider. Successful complete snapshots are cached for five minutes in the existing SQLite cache, keyed by a credential hash. Concurrent same-process fetches coalesce. There is no automatic paid-provider polling or retry loop.
- Authentication/account/limit errors are sanitized and persisted as cooldowns. `Retry-After`, `error.retry_after_seconds` and `error.reset_at` are respected. A newer provider failure blocks generation from the previous snapshot until a successful recovery; it does not delete archives. No provider error body, arbitrary message, token or authorization header is returned or persisted.
- Provider event IDs are kept separate from nflverse/ESPN IDs. Home/away identity and kickoff must match a unique verified upcoming free-schedule event within 60 seconds. Conflicting event/quote identities are withheld. Prop team and kickoff must also agree; when the provider returns a null team, the existing actual roster/history pipeline must verify the team, and the UI labels that identity as roster-derived. A conflicting provided team is never silently replaced; a name-only event join is insufficient.
- Only documented full-game NFL passing yards, passing TDs, rushing yards, rushing attempts, receiving yards and receptions are mapped to existing modeled markets. Q1, unsupported markets, suspended/closed/removed props, missing prices, invalid lines and unknown player identities do not become picks. Existing separate first-quarter analysis is unchanged.
- Source `ok`/`delayed`, real observation time, feed `as_of` and delay metadata are required. Source `stale`/`down`/unknown, missing timestamps, future timestamps beyond one minute and source/quote ages or delays beyond the existing 30-minute maximum are excluded. Original timestamps are never replaced with retrieval time. Five-minute-delayed data stays labeled delayed, never real-time.
- Every option has exactly **1 QB, 2 RB, 2 WR, 1 TE**, unique players, no more than three legs per game, verified historical/roster provenance, recent role support and the existing injury/pricing/sample restrictions. Each card gives estimates, historical averages, defense rank when available, selection rationale and risk warnings.
- No calibration gate is weakened. These selections are explicitly research only, even if a caller claims model validation; TEST MODE remains research only. Theoretical combined prices and joint probabilities are not accepted sportsbook parlay quotes. No new provider samples are automatically promoted into calibration or historical performance.
